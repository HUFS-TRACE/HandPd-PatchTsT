# HandPD-PatchTST

NewHandPD 스마트펜 6채널 시계열로 파킨슨 여부를 분류하고,
**Early Exit**으로 연산량을 줄이면서 정확도를 유지할 수 있는지 검증한다.

```
model.py           PatchTST 분류 모델 (고정깊이 baseline)
earlyexit.py       Early Exit PatchTST (층마다 출구) + 임계값 스윕
train.py           baseline 학습
evaluate.py        FLOPs 측정 · Pareto 곡선 · 하이퍼파라미터 스윕 · hard/soft voting
plot_combined.py   고정깊이 + Early Exit 통합 그림
summarize_seeds.py 여러 seed 결과를 평균±표준편차로 집계
dataset.py         npz 로드 · 피험자 단위 K-Fold
```

**결론 미리보기** — 고정깊이 최고 성능(86.7%)을 Early Exit이 **6.3배 적은 연산**으로 동일하게 달성. 자세한 수치는 [§6 결과](#6-결과-datawindowsnpz--1초-윈도우-5-fold-seed-42).

## 2. 실행

```bash
# baseline 학습
python train.py --data-path data/windows.npz

# FLOPs 표만 (학습 없이 수초)
python evaluate.py --dry-run

# 설정별 학습 + Pareto 곡선  → results/pareto.{csv,png}
python evaluate.py --data-path data/windows.npz

# 일부 설정만
python evaluate.py --configs tiny,baseline,deep

# Early Exit 학습 + 임계값 스윕 → results/earlyexit.{csv,png}
python earlyexit.py --data-path data/windows.npz --n-layers 6

# 두 실험을 한 장에 겹쳐 그리기 → results/combined.png
python plot_combined.py

# ── 하이퍼파라미터 스윕 ──
python evaluate.py --suite patch --data-path data/windows_2s.npz   # 패치 크기 축
python evaluate.py --suite size  --data-path data/windows_2s.npz   # 모델 크기 축
python evaluate.py --suite size --lr 3e-4 --batch-size 32          # 학습률·배치

# epoch별 train/val loss 출력 + 곡선 저장
python evaluate.py --suite size -v

# seed를 바꿔 반복한 뒤 평균±표준편차로 집계 (⚠️ 필수, §5-1 참고)
python evaluate.py --suite size --seed 1
python summarize_seeds.py "results/pareto_size_2s*.csv"
```

산출물은 스윕·데이터·학습률·배치·seed별로 파일명이 갈려 서로 덮어쓰지 않는다.
(예: `results/pareto_size_2s_lr0.0003_s1.csv`)

## 3. 실험 조건

### 공통

| 항목 | 값 | 비고 |
|---|---|---|
| 분할 | 피험자 단위 GroupKFold 5-fold + val 10% | 같은 사람이 train·test에 걸치지 않음 (`dataset.py`에서 assert로 검증) |
| 정규화 | RevIN (채널별, 윈도우 자체 통계) | 윈도우마다 자기 통계로 정규화 → 구조적으로 누수 없음 |
| 손실 | CrossEntropy + 클래스 가중치 (정상 2.0 / 환자 1.0) | 실제 비율 4867:8607 ≈ 1:1.77 |
| 최적화 | AdamW, lr 1e-3, weight decay 1e-4 | ReduceLROnPlateau (factor 0.5, patience 3) |
| 조기중단 | val loss 기준 patience 10 | 최적 체크포인트로 test 평가 |
| epochs / batch | 50 / 64 | |
| seed | 42 | |

### 모델 (baseline)

| 항목 | 값 |
|---|---|
| 패치 / stride | 16 / 8 (50% 겹침) |
| d_model / heads / layers / d_ff | 128 / 8 / 3 / 256 |
| dropout / head dropout | 0.2 / 0.2 |
| 정규화 순서 | **pre-LN** (norm_first=True), 활성함수 GELU |
| 채널 처리 | channel-independent — 6채널을 공유 백본으로 각각 통과 후 concat |

### Early Exit

| 항목 | 값 |
|---|---|
| 백본 | baseline과 **동일** (RevIN · sinusoidal PE · pre-LN · GELU) |
| 출구 | 인코더 층마다 1개, 구조는 baseline head와 동일 |
| 층 수 | 6 (기본) |
| 학습 | 모든 출구 손실을 **동일 가중으로 합산**해 공동 학습 |
| 추론 | `max(softmax) >= 임계값`인 첫 출구에서 종료, 마지막 층은 무조건 종료 |
| 임계값 스윕 | 0.50 ~ 1.00, 0.025 간격 (21개) |

> 임계값 스윕은 **fold당 학습 1회** 후 모든 출구의 확률을 캐시해두고 재계산만 한다(표준 offline 평가). 임계값을 아무리 촘촘히 늘려도 학습 비용은 그대로다.
> 임계값 하한이 0.50인 이유: 2클래스에서 `max(softmax)`의 최솟값이 0.5라 그 아래는 전부 1층 종료로 동일하다.

## 4. 평가 지표

| 지표 | 설명 |
|---|---|
| **윈도우 정확도** | 윈도우 단위. 표본이 수천 개라 값은 안정적이지만 낙관적 |
| **피험자 정확도** | 윈도우 다수결 → 사람 단위. **실제 사람은 61명뿐**이라 이쪽이 일반화 성능의 정직한 지표 |
| ROC-AUC | 임계값 무관 성능 |
| **MFLOPs** | 샘플 1개당 순전파 FLOPs |

**FLOPs 측정 방법** — `torch.utils.flop_counter.FlopCounterMode` (PyTorch 내장, 외부 라이브러리 불필요)

- 관례대로 **행렬곱 기준**이며 MAC이 아닌 실제 FLOPs(곱셈+덧셈)를 센다.
- softmax · LayerNorm · 활성함수는 제외 (전체의 1% 미만, 표준 관례).
- ⚠️ **반드시 `train()` 모드에서 측정한다.** `eval()`이면 `nn.TransformerEncoder`가 fused fast-path로 빠져 카운터가 인코더 연산을 통째로 놓친다(층 수를 바꿔도 값이 안 변하는 증상). dropout은 FLOPs에 영향이 없어 train 모드로 재도 값은 같다.
- Early Exit은 **출구별 누적 FLOPs**를 각각 측정한 뒤, 실제 종료 지점 분포로 가중평균해 평균 연산량을 낸다. "사용 층수 비율" 같은 근사가 아니라 실측값이다.

## 5-1. ⚠️ 먼저 읽을 것 — 단일 seed 결과는 신뢰할 수 없다

`data/windows_2s.npz`에서 설정 10종을 seed를 바꿔 반복한 결과:

| 비교 | 변동폭 |
|---|---|
| **설정을 다 바꿔서** 얻는 최대 차이 | **3.3%p** (85.3% → 82.0%) |
| **같은 설정에서 seed만** 바꿨을 때 | **최대 11.5%p** (86.9% → 75.4%) |

**하이퍼파라미터를 아무리 튜닝해도 seed 하나 바꾸는 것보다 영향이 작다.**
원인은 표본 규모다 — 피험자 61명, fold당 test 12명이라 **1명이 8.3%p**다.

실제로 `p50` 설정은 seed 42에서 91.7%가 나왔지만 seed 7에서는 80.4%였다(4개 평균 86.4%).
처음 91.7%만 보고 "90% 돌파"라고 결론냈다면 재현되지 않았을 것이다.

> **규칙: 결과는 반드시 seed 3개 이상의 평균 ± 표준편차로 보고한다.**
> `python summarize_seeds.py "results/pareto_*_2s*.csv"` 로 집계할 수 있다.

### 6-1. 고정깊이 설정 스윕

| 설정 | 패치/stride | d_model | 층 | MFLOPs | 파라미터 | 윈도우acc | 피험자acc | ROC-AUC | Pareto |
|---|---|---|---|---|---|---|---|---|---|
| tiny | 32/16 | 64 | 1 | 31.2 | 36,366 | 0.763 | 78.6% | 0.843 | ★ |
| small | 32/16 | 64 | 2 | 60.9 | 69,838 | 0.769 | 83.6% | 0.846 | ★ |
| coarse | 64/32 | 128 | 3 | 152.8 | 407,310 | 0.764 | 83.6% | 0.830 | |
| **mid** | 16/8 | 64 | 2 | **146.3** | 68,814 | 0.761 | **85.1%** | 0.841 | ★ |
| baseline | 16/8 | 128 | 3 | 729.9 | 401,166 | 0.766 | 85.1% | 0.836 | |
| wide | 16/8 | 192 | 3 | 1533.6 | 896,654 | 0.765 | **86.7%** | 0.846 | ★ |

- **연산량 49배 범위(31 → 1534 MFLOPs)에서 정확도가 78.6~86.7%로 거의 평평.** 윈도우 정확도는 0.761~0.769로 사실상 구분되지 않고 ROC-AUC도 0.830~0.846이다.
- **baseline은 mid에게 지배당한다** — 연산 5배·파라미터 6배인데 피험자 정확도가 소수점까지 동일(85.13%)하고 AUC는 오히려 낮다.
- 1층(tiny)만 뚜렷이 낮다(78.6%, 윈도우·AUC 모두 최하위권). **2층 이상이면 더 키워도 얻는 게 없다.**
- wide가 86.7%로 최고지만 mid와 **피험자 1명 차이**를 연산 10.5배로 산 것이다.

### 6-2. Early Exit (6층, 임계값 스윕)

| 임계값 | MFLOPs | 연산% | 평균 출구 | 윈도우acc | 피험자acc | ROC-AUC |
|---|---|---|---|---|---|---|
| **0.50** | **245.3** | **16.8%** | 1.00 | 0.752 | **86.7%** | 0.837 |
| 0.55 | 263.8 | 18.1% | 1.08 | 0.757 | 85.0% | 0.838 |
| 0.60 | 295.4 | 20.3% | 1.21 | 0.760 | 85.0% | 0.838 |
| 0.70 | 408.1 | 28.0% | 1.67 | 0.757 | 83.5% | 0.837 |
| 0.80 | 578.7 | 39.7% | 2.38 | 0.750 | 83.5% | 0.835 |
| 0.90 | 822.2 | 56.4% | 3.38 | 0.747 | 81.8% | 0.834 |
| 0.95 | 1000.5 | 68.7% | 4.12 | 0.746 | 81.8% | 0.834 |
| **1.00** (조기종료 OFF) | **1456.7** | **100%** | 6.00 | 0.746 | **81.8%** | 0.834 |

> **연산 5.9배 절감(1457 → 245 MFLOPs)하면서 피험자 정확도가 오히려 +4.9%p 상승(81.8 → 86.7%).**

- **곡선이 우상향이 아니다.** 연산을 늘릴수록 정확도가 **떨어진다** — 세 지표(윈도우·피험자·AUC)에서 모두 같은 방향.
- 깊은 층은 연산만 소비하고 정확도에 기여하지 않으며(소규모 데이터 과적합), 조기종료가 이를 잘라내 **정규화 효과**까지 낸다.
- 조기종료의 올바른 대조군은 **같은 모델의 thr 1.0**이다. 별도 학습한 6층 모델과 비교하면 "조기종료 효과"와 "학습 방식 차이"가 섞인다.

### 6-3. 통합 비교

| | 연산량 | 피험자 정확도 |
|---|---|---|
| 고정깊이 최고 (wide) | 1533.6 MFLOPs | 86.7% |
| **Early Exit (thr 0.50)** | **245.3 MFLOPs** | **86.7%** |

> **동일한 정확도를 6.3배 적은 연산으로 달성.** 저사양 기기 스크리닝이라는 목표에 직접 부합한다.

통합 Pareto 프론티어: `tiny → small → mid → EE(thr 0.50)`.
**baseline · coarse · wide는 모두 지배당해 프론티어에서 탈락한다.**

- 어떤 설정도 90%를 안정적으로 넘지 못한다. 병목은 모델이 아니라 데이터 규모다.

### 6-3-1-1. ⭐ 파라미터 축별 효과 vs seed 노이즈

12개 파라미터를 축별로 나눠 각각 seed 3~4개로 반복했다(`python analyze_all.py`).
판정은 **최고 그룹과 최저 그룹의 평균 차이를 "차이의 표준오차"로 나눈 t값**으로 한다.
표준편차가 아니라 평균의 표준오차(`std/√n`)를 써야 seed를 늘렸을 때의 안정화가 반영된다.

| 축 | 최고−최저 | t | 판정 |
|---|---|---|---|
| **fold 수** (3/5/10) | **7.8%p** | **3.54** | ⭐ **효과 있음** |
| 패치 크기 (16~200) | 3.7%p | 1.73 | 판단 보류 |
| 모델 크기 (d32~d128) | 3.3%p | 1.02 | 판단 보류 |
| patience (10/30) | 2.8%p | 0.98 | 노이즈에 묻힘 |
| 학습률 (3e-4~3e-3) | 1.7%p | 0.99 | 노이즈에 묻힘 |
| head 수 (2/4/8) | 1.6%p | 0.92 | 노이즈에 묻힘 |
| 배치 크기 (32/64/128) | 1.1%p | 0.48 | 노이즈에 묻힘 |

**seed 노이즈: 같은 조건에서 평균 5.8%p, 최대 11.5%p 변동** (조건 22개 기준)

> **모델 하이퍼파라미터 6개 축 중 유의미한 것은 하나도 없다(t < 2).**
> 반면 평가 프로토콜인 `n_folds`만 유일하게 유의미하며, 그 효과가 다른 모든 축의 2배 이상이다.
> **모델을 어떻게 만드느냐보다 어떻게 평가하느냐가 결과를 더 크게 좌우한다.**

#### fold 수 (유일하게 유의미한 축)

| folds | fold당 test | hard 정확도 |
|---|---|---|
| 3 | 20명 | 77.5 ± 2.7 |
| **5** | **12명** | **85.3 ± 2.7** |
| 10 | 6명 | 78.9 ± 1.2 |

3과 10 모두 5보다 7%p 낮다. 원인은 서로 다르다고 본다.

- **3-fold**: train이 61명의 2/3인 40명뿐이라 학습 데이터가 부족하다.
- **10-fold**: train은 55명으로 늘지만 `val`이 5~6명까지 줄어든다. `subject_kfold`가 train_val에서 10%를 val로 떼는 구조라, val이 이 정도로 작으면 val loss가 불안정해져 **조기중단이 엉뚱한 지점에서 걸린다.** 표준편차가 1.2로 가장 작으면서 평균만 낮은 것이 이 해석과 맞는다(노이즈가 아니라 체계적 저하).

또한 `GroupKFold`는 층화를 하지 않으므로(§7), fold당 6명이면 클래스 비율이 심하게 깨진 fold가 생길 수 있다.

#### 학습률 — 성능과 재현성의 트레이드오프

| lr | 평균 | 표준편차 |
|---|---|---|
| 3e-4 | 83.7 | **± 0.1** |
| 1e-3 (기본) | **85.3** | ± 2.7 |
| 3e-3 | 83.6 | ± 1.4 |

`3e-4`는 정확도가 1.6%p 낮지만 **표준편차가 0.1로 seed를 거의 타지 않는다.** 재현성이 중요한 보고에는 이쪽이 유리할 수 있다.

#### patience — 더 학습시켜도 나아지지 않는다

`--patience 30 --epochs 150`으로 조기중단을 크게 늦춰도 85.3% → **82.6%**로 오히려 떨어졌다(t=0.98, 유의하지는 않음).
§6-3-3의 학습 곡선 관찰("val loss는 ep 2~9에서 최저")과 방향이 일치한다.

### 6-3-2. hard vs soft voting

윈도우 예측을 피험자 단위로 합칠 때 두 방식을 비교했다.

- **hard**: 윈도우마다 1표. 확신도 0.51이든 0.99든 같은 무게.
- **soft**: 윈도우별 `P(환자)`를 평균낸 뒤 0.5와 비교. 확신도가 표의 무게에 반영된다.

설정 10종 × seed = **34개 비교** 결과:

| | |
|---|---|
| soft 우세 | **13** |
| hard 우세 | 4 |
| 동률 | 17 |
| 평균 차이 | **+0.45%p** |
| 이항검정 (동률 제외, n=17) | **p = 0.0245 → 유의미** |

> **결론: soft voting을 쓰는 편이 낫다.** 통계적으로 유의미하게 지는 경우가 적고, 계산 비용도 동일하다.
> 다만 **이득이 +0.45%p로 피험자 1명(1.6%p)보다 작아** 실용적 차이는 미미하다.
> "soft로 바꿔 성능이 올랐다"고 주장하기에는 근거가 약하다.

### 6-3-3. 학습 곡선 — epoch을 늘릴 필요가 없다

`-v` 옵션으로 epoch별 train/val loss를 출력하고 `results/loss_curves_*.png`에 저장한다.

| 설정 | val loss 최저 | 조기중단 |
|---|---|---|
| p32 | ep 3 | 15.8 |
| p50 | ep 9 | 16.8 |
| p100 | ep 8 | 13.4 |
| p200 | ep 2 | 12.4 |

`--epochs 50`으로 실행하지만 **조기중단이 13~17에서 걸려 아무도 50을 쓰지 않는다.**
val loss 최저는 2~9에서 나오고 그 뒤로는 train loss만 내려간다(train/val 간극 +0.17~+1.15).
**epoch을 늘려도 개선되지 않으며, 필요한 것은 더 많은 데이터나 강한 정규화다.**

### 6-4. 해석 시 주의

- **피험자 61명, fold당 test 12~13명 → 1명 ≈ 1.6%p.** 86.7% vs 81.8%는 피험자 3명 차이다. 1~2%p 차이(예: 83.6 vs 85.1)는 노이즈로 봐야 한다.
- 신뢰할 수 있는 것은 개별 점수가 아니라 **여러 설정·지표에서 일관되게 나타나는 방향성**이다: ① 2층 이상에서 모델 확대의 이득 없음 ② 조기종료가 연산을 크게 줄이면서 정확도를 잃지 않음. 두 결론 모두 윈도우 정확도·ROC-AUC에서도 동일하게 확인된다.
- 윈도우 정확도(0.75 전후)가 피험자 정확도(0.82~0.87)보다 낮은 것은 정상이다 — 다수결이 개별 윈도우의 오류를 상쇄한다.
- **모델 하이퍼파라미터로는 90%에 도달할 수 없다**(§6-3-1-1). 6개 축 어느 것도 통계적으로 유의미하지 않았고, 최고 기록 91.7%는 재현되지 않았다(같은 설정, seed 7에서 80.4%). 90%를 목표로 한다면 튜닝이 아니라 **표본 수를 늘리거나 평가 프로토콜을 재설계**해야 한다.

## 7. 알려진 이슈 / 검토 필요

- **`GroupKFold`는 층화(stratify)를 하지 않는다.** fold마다 정상/환자 비율이 흔들릴 수 있어 `StratifiedGroupKFold` 검토 필요.
- **클래스 가중치가 상수 2.0/1.0로 고정**돼 있다. 실제 비율(1:1.77)이나 fold별 train 분포에서 계산하는 편이 정확하다.
- **피험자 61명 기준 1명 = 약 1.6%p.** fold당 test 12~13명이라 정확도가 큰 단위로 양자화된다. 개별 fold 값이나 1~2%p 차이는 노이즈로 봐야 하고, 여러 설정에서 일관되게 나타나는 **방향성**만 신뢰할 수 있다.
