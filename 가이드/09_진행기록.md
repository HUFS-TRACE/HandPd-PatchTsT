## 사고 기록 — Colab 세션이 회수됐다 (23:20)

occlusion을 4/5 fold까지 돌린 상태에서 **Colab이 VM을 회수**했다
(`colab log`의 `session_terminated reason=pruned`). 체크포인트가 VM에만 있었기
때문에 **학습부터 다시** 해야 했다.

**교훈 셋 — 다음에 반드시 지킬 것**

1. **산출물은 생기는 즉시 로컬로 내린다.** 체크포인트를 학습 직후 받아뒀다면
   occlusion만 다시 돌리면 됐다. "다 끝나면 한 번에 받자"가 화근이었다
2. **긴 작업은 VM 안에서 체인으로 묶는다.** 로컬에서 단계마다 `colab exec`을
   부르면 그 사이 세션이 끊겼을 때 이어지지 않는다
3. **T4 재할당이 곧바로 되지 않는다.** 회수 직후 `TooManyAssignmentsError`가
   났다(회수된 할당이 서버에 남음). CPU 세션은 즉시 됐으므로 GPU 쿼터 문제다.
   3분 간격 재시도로 3번째에 잡혔다

**복구 후 구성 — 두 갈래 병행**

| 갈래 | 모델 | 장치 | 비용 | 역할 |
|---|---|---|---|---|
| 정본 | `p16d128L1` (588 MFLOPs) | Colab T4 `hp2` | 학습 25분 + occlusion 40분 | 가이드가 지정한 X1 대상 |
| 보험 | `d64L2` (38 MFLOPs) | 로컬 CPU | 학습 1.5시간 + occlusion 26분 | GPU를 또 잃어도 결과가 남는다 |

**`d64L2`를 고른 이유** — 가이드가 정한 **정적 축 대표**(38 MFLOPs)이고,
`p16d128L1`보다 15배 싸서 CPU로도 돌아간다. 실측으로 확인했다.

| 모델 | CPU 학습(5-fold) | CPU occlusion |
|---|---|---|
| `p16d128L1` | **21.6시간** — 불가능 | 5.0시간 |
| `d64L2` | **1.5시간** | 26분 |

논문 관점에서도 손해가 아니다. `d64L2`는 ⑥에서 "실제로 쓰라"고 권고할 모델
이므로, 그 모델의 판단 근거를 설명하는 것이 오히려 배포 시나리오에 가깝다.
둘 다 나오면 **설명이 모델 규모에 따라 달라지는지**까지 볼 수 있다.

### 방법론 발견 — 평균 마스킹은 클래스 중립이 아니다

전채널 동시 가림의 평균 하락폭(1000ms):

| 모델 | 정상군 | 환자군 | 방향 |
|---|---:|---:|---|
| `p16d128L1` | +0.121 | −0.039 | 가리면 **환자 쪽**으로 민다 |
| `d64L2` | −0.051 | +0.136 | 가리면 **정상 쪽**으로 민다 |

부호 있는 하락폭을 중요도로 쓰면 모델 간 비교가 뒤집힌다. 주 중요도를
**|Δp|**로 바꾸고 두 정의를 모두 보고하도록 `--importance` 옵션을 넣었다.

### 부호가 갈린 이유 — 두 모델은 다른 대역을 본다

대역만 바꿔 같은 검정을 반복했다 (ch2 · 환자군).

| 대역 | `d64L2` (패치 100ms) | `p16d128L1` (패치 16ms) |
|---|---:|---:|
| 2–4 Hz | −0.48 | −0.68 * |
| **4–6 Hz** | **+0.87** * | **−1.01** * |
| **6–8 Hz** | **+1.10** * | −0.37 |
| **8–12 Hz** | +0.34 | **+0.88** * |
| 12–20 Hz | −1.09 * | **+0.77** * |

`d64L2`는 **4–8Hz**(떨림 대역), `p16d128L1`은 **8–20Hz**를 쓴다.
부호가 반대였던 게 아니라 **보는 대역이 다른 것**이었다.

**해석 — 패치 길이가 볼 수 있는 대역을 정한다.** 패치는 원신호 구간을 벡터로
선형 사상하므로, 패치 안에 들어오는 주기는 임베딩이 직접 표현하고 그보다 긴
주기는 어텐션으로 조립해야 한다. 100ms 패치는 5Hz의 반주기를, 16ms 패치는
20Hz의 1/3 주기를 담는다.

**논문에서의 의미가 크다** — 패치 설정은 조정 손잡이가 아니라 **표현의
선택**이며, ⑥의 "표현 축" 주장과 직접 이어진다.

**단, 상관 관찰이다.** 패치 길이만 바꾼 통제 실험이 아니므로 가설로만 쓴다.

### 산출물 파일명에 조건을 전부 넣을 것 (두 번 물렸다)

**같은 종류의 사고를 두 번 겪었다.** 조건을 바꿔 돌린 결과가 이전 결과를
같은 이름으로 덮어썼다.

| 빠졌던 조건 | 무슨 일이 있었나 |
|---|---|
| 마스킹 방식 | 보간 실행이 평균 마스킹 결과를 덮어쓰기 직전에 발견해 중단 |
| **검정 대역** | **대역 훑기(마지막 12~20Hz)가 4~6Hz 정본을 실제로 덮어썼다.** 시드 종합 스크립트가 `p16d128L1` 환자 ch2를 +0.768로 보고해서 발견 (정본은 −1.010) |

두 번째는 실제로 덮어썼고, **다른 스크립트를 돌리다가 우연히 발견**했다.
보고서 수치 자체는 맞았지만 디스크의 파일이 그 값이 아니었다.

지금은 파일명에 `대역`·`마스킹`·`중요도 정의`가 모두 들어간다. 기본 조건
(4~6Hz · mean)만 접미사 없이 두어 기존 이름과 어긋나지 않게 했다.

> **교훈** — 조건을 바꿔 돌릴 수 있는 스크립트는 그 조건이 파일명에
> 들어가야 한다. 안 그러면 마지막 실행이 정본 행세를 한다.

## 총괄 점검 결과 (2026-09-06)

### fold 일관성 감사 — 현재는 이상 없음, 단 위험은 남아 있다

리포 전체에서 `GroupKFold`·`GroupShuffleSplit`을 직접 만드는 코드는
**`dataset.py` 한 곳뿐**이다. `train.py` · `evaluate.py` · `earlyexit.py`가
모두 `protocol.get_folds()`를 거친다. `occlusion.py`는 fold를 새로 만들지
않고 체크포인트에 저장된 `test_subjects`를 쓰므로 더 강하게 일치한다.

**그런데 원종윤의 경량 ML 스크립트(E1·E2·E3)가 아직 리포에 없다.**
가이드가 지목한 위험 지점은 아직 열려 있는 셈이다. 코드가 생길 때 아래를
그대로 쓰면 어긋나지 않는다.

```python
# 경량 ML(sklearn)에서도 딥러닝과 같은 분할을 쓰는 방법
import argparse
from protocol import add_common_args, apply_config_file, get_folds
from dataset import load_npz

p = argparse.ArgumentParser(); add_common_args(p)
args = apply_config_file(p.parse_args())          # --config configs/protocol.yaml
X, y, subject_id, task = load_npz(args.data_path)

for tr, va, te in get_folds(subject_id, y, args):  # sklearn GroupKFold를 직접 만들지 말 것
    ...
```

> **직접 `GroupKFold(n_splits=5).split(...)`을 부르면 val 분리가 빠져서**
> train 크기가 달라지고, 딥러닝과의 비교가 성립하지 않는다.

## TimeSeg (X0) — 판정: 통과, 단 패치 필요

- 논문: **TimeSeg: An Information-Theoretic Segment-Wise Explainer for
  Time-Series Prediction** — Hwijin Kim, Jaeho Kim, Changhee Lee, ICLR 2026
- 코드: https://github.com/kimhwijin/TimeSeg
- OpenReview: `alt9mSWULk` (웹 봇 차단, API 비공개 — PDF는 로그인 필요)
- **PPO 기반 강화학습이 맞다.** 제목의 "information-theoretic"은 목적함수
  (분할 선택을 상호정보량 최대화로 정의) 이야기고, 최적화는 PPO다

### 재현 결과 (WSL CPU, GunPoint)

| 단계 | 결과 |
|---|---|
| 블랙박스 `--epoch 1` (저자 기본값) | 9초. test_acc 0.50 — **스모크 테스트일 뿐** |
| 블랙박스 `--epoch 50` | 53초. **test_acc 0.730 / AUROC 0.763** |
| explainer (PPO, 5 epoch) | **171~259초**, 끝까지 완주 |
| explainer 결과 | 평균 선택 길이 **18/150 = 신호의 12%**, 그것만으로 **SUFF AUROC 0.627** (전체 신호 0.763) |

**함정** `blackbox_train.py`는 체크포인트가 이미 있으면 `Skip`하고 그냥
반환한다. epoch을 바꿔 다시 돌리려면 `model_ckpt/{dataset}/`를 먼저 지울 것.
안 지우면 이전 모델로 explainer가 돌아가며, 결과가 소수점까지 같게 나온다.

→ 우연 수준 분류기(0.396)와 제대로 학습된 분류기(0.627)에서 결과가 뚜렷이
갈린다. **파이프라인이 실제로 작동한다는 확인이다.**

### 환경 구성에서 깨진 곳 4가지 (다시 할 사람을 위해)

1. `time_interpret` — 패키지명과 **import명이 다르다**. `import tint`
2. TimeSynth — `setup.py install` 실패. `pytest-runner` 선설치 후
   `uv pip install "git+https://github.com/TimeSynth/TimeSynth.git"`
3. `txai` (TimeX, Queen et al. 2023) — pip 설치본에 **하위 모듈 누락**.
   저장소를 clone해 PYTHONPATH에 얹어야 한다
4. **`txai`가 numpy와 충돌** — `np.warnings`는 numpy 1.24에서 삭제됐는데
   TimeSeg은 numpy 1.26을 핀한다. `datasets/__init__.py`가 7개 로더를
   최상단에서 몰아 import하므로 **GunPoint 하나 쓰려 해도 전부 죽는다**
   → 로더별 독립 import(try/except)로 패치함

### 우리 데이터 이식 시 쟁점

- **다변량이 배선돼 있지 않다.** `main_ppo.py`의 `d_in = 1`(73·271행)과
  `datasets/__init__.py`의 모든 `num_features = 1`이 하드코딩. 6채널을 넣으려면
  데이터모듈→정책망 경로 전체를 손봐야 한다
- **채널 선택이 불가능하다.** `utils/env.py`가 마스크를 `(B,T,1)`로 만들어
  전 채널에 브로드캐스트한다. TimeSeg은 "어느 시간 구간"만 고른다
  - X2(대역 파워 검정)는 **영향 없다** — 구간이 공통이어도 파워는 채널별로
    계산해 채널별로 검정하면 된다
  - X3(채널별 heatmap)는 **불가능**. occlusion으로 해야 한다
  - 채널 축 추가는 4개 파일 100~150줄 규모(분포·정책망·env·main_ppo).
    다만 행동 공간이 T×T→T×T×C로 커져 수렴 위험이 있다
- **시퀀스 길이** 저자 최대 360 vs 우리 2000. 행동 공간이 5.5배.
  CPU 259초는 길이 150 기준이므로 **우리 데이터는 GPU 필수**

### 결론

X4는 살아 있다. 다만 순서를 지킨다.
**원본 TimeSeg(시간 구간만)으로 먼저 수렴을 확인한 뒤에** 채널 확장을 검토한다.
개조부터 하면 실패했을 때 원인이 개조인지 데이터인지 못 가린다.

# 2026-09-07 오후 — 팀 결과 반영 (확인서 폴더)

원종윤 님 보고서 3건(`E1E2` · `v2` · `v3`)을 받았다. **하나가 ⑤의 검정 대상을

## E1·E2 — 저차원 축은 떨림 대역이 아니다

| 피처 | 창 AUC |
|---|---:|
| 4~6Hz 떨림 대역, 6채널 전부 (E1) | .6125 |
| **가속도 SD · 그립력 하나** (E2) | **.7274** |
| 단일 축압력 떨림 대역 | **.4330** (우연 이하) |
| greedy 4개 피처 | .7974 (딥러닝 .8629의 93%) |

단일 성능 상위 8개에 떨림 대역이 **하나도 없다.** 원종윤은 보고서에서
"⑤단계 XAI에서 무엇을 검정할지가 여기서 바뀐다 — 떨림 대역이 아니라
변동성이 큰 구간을 짚는지 봐야 한다"고 명시했다.

## 그래서 X2를 변동성으로 재검정했다

`bandpower_test.py`에 `--statistic` 옵션을 넣고(속도 SD · 가속도 SD · 진폭 SD)
시드 3개로 다시 돌렸다. **결과가 ⑤의 주장 형태를 바꾼다.**

| 구간 통계 | 환자 | 정상 | 군 특이성 |
|---|---|---|---|
| 속도·가속도 SD | −0.9 ~ −1.9 (전 채널) | −0.3 ~ −1.9 (전 채널) | **없음** |
| 진폭 SD | +0.75 ~ +1.30 (전 채널) | +0.94 ~ +1.57 (전 채널) | **없음** |
| **4~6Hz 상대파워** | 축압력 **+0.85** | 축압력 −0.06 | **있음** |

**모델이 어디를 보는지는 클래스와 무관한 신호 성질이 정한다** — 진폭이 크고
속도 변동이 작은 구간, 즉 **크고 느린 움직임**. 효과 크기가 |dz| 1.5~1.9로
떨림 대역(0.85)보다 크다. E2의 2위 피처가 저주파·기울기Y인 것과 맞물린다.

### 왜 이것이 ⑤를 무너뜨리지 않는가

**마스킹 절차는 라벨을 모른다. 그러므로 절차에서 오는 효과는 반드시 군에
무관하다.** 실제로 변동성 효과는 양 군에서 같은 방향·비슷한 크기다. 반면
축압력의 4~6Hz는 환자에서만 양수이므로 **절차로 설명될 수 없다.**

게다가 저주파가 지배하는 구간을 고르면 4~6Hz 상대파워는 낮아지는 게 자연스럽고
실제로 대부분 채널에서 음수인데, **환자 축압력만 그 경향을 거슬러 양수**다.

### 주장의 형태를 이렇게 바꾼다

- (X) "모델이 떨림을 본다"
- (O) **"모델이 어디를 보는지는 크고 느린 움직임이 정하고, 환자에서는 그
  구간에 떨림 대역 에너지가 추가로 실린다"**

④의 저차원 축(변동성·저주파)과 오히려 더 잘 연결된다.

### 남은 의심 — RevIN 상호작용

진폭 SD가 큰 구간을 가리면 창 전체의 표준편차가 크게 바뀌고, RevIN이 창
단위로 재정규화하므로 나머지 구간까지 스케일이 변한다. **진폭 SD 양수 효과의
일부는 이 절차적 상호작용일 수 있다.** 군에 무관하므로 ⑤의 결론에는 영향이
없지만, 논문 방법 절에 한계로 적어야 한다.

## V2 — 사람 축은 조건이 성립한다 (가이드 예상과 반대)

3/3 시드로 틀리는 피험자 **2명**, 2/3 시드 4명, 1/3 시드 6명.
"5명에 집중"이라던 초판을 원종윤이 스스로 정정했다. 깊이를 늘려도 그 2명은
구제되지 않는다(순이득 3명, 확률 변화 .083).

**단 2명으로 "어려운 표본이 실재한다"를 주장하는 것은 약하다.** 논문에는
"재현되는 오분류가 소수 존재하나 그 규모가 작아 단정하지 않는다"로 쓴다.

## V3 — 시간 축은 "이득이 없어서"가 아니라 "오류를 통제할 수 없어서" 막힌다

사전 등록 게이트 불통과 (C 유형 = 확신을 갖고 오분류, 3시드 평균 8명).

|---|---|---|

## ③단계 서사가 통째로 바뀐다

가이드 02의 "세 방향 모두 조건 불성립"은 **틀렸다.** 원종윤이 정리한 대체
문장이 정확하다.

> 세 방향 모두 **"메커니즘은 작동하는데 어려운 사람에게 듣지 않는다"**.
> Early Exit이 실패한 이유는 난이도 분산의 부재가 아니라, **난이도와 계산량
> 요구가 연결되어 있지 않기 때문**이다.

**이 편이 더 강한 진술이다.** "조건이 없다"는 확률 분포 하나로 반박당하지만,
"조건은 있는데 연결이 없다"는 구체적이고 방어 가능하다.

원종윤 님 E1·E2가 "⑤의 검정 대상이 바뀐다"고 지적한 뒤 이어서 한 것들.
**셋 다 결과를 냈고, 하나는 내 해석을 기각했다.**

## A. 과제별 분리 — E1과 독립적으로 같은 결론

`bandpower_test.py --task`로 4개 과제를 분리했다 (`d64L2`, 시드 3개, 1000ms,
|Δp|, 축압력 ch2).

| 과제 | 환자 dz | 정상 dz | 환자−정상 |
|---|---:|---:|---:|
| **spiral** | **+0.79** | −0.07 | +0.87 |
| **meander** | **+0.65** | −0.38 | +1.03 |
| circle | +0.41 | +0.09 | +0.32 |
| **diadochokinesis** | **−0.11** | +0.31 | −0.42 |
| 전체(뭉침) | +0.85 | −0.06 | +0.91 |

**그림 그리기 과제(spiral·meander)에서만 효과가 살아 있다.**

- `circle`이 절반으로 줄어드는 것은 **E1의 "circle 떨림 대역 AUC .4084(우연
  이하)"와 방향이 같다.** 피처 기반 회귀와 딥러닝 occlusion이라는 서로 독립인
  두 분석이 같은 결론에 도달했다
- `diadochokinesis`는 **부호가 뒤집힌다.** 손을 빠르게 뒤집는 동작이라
  4~6Hz가 떨림이 아니라 동작 주파수 그 자체다

**전체를 뭉쳐 낸 +0.85는 사실상 spiral·meander가 만든 값이다. 논문에는 반드시
과제별로 분리해 싣는다** — E1이 요구한 것과 같은 결론.

## B. RevIN 교란 정량화 — 우려보다 작다

`revin_confound.py` 신규. 구간을 가렸을 때 창 표준편차가 얼마나 변하는지를
모델 없이 계산하고, 그것이 occlusion 중요도를 얼마나 설명하는지 순위 상관으로
쟀다 (`d64L2` 시드 42, 200ms).

| 채널 | 환자 rho | 정상 rho | 설명력 R² |
|---|---:|---:|---:|
| ch2 축압력 | 0.340 | 0.363 | **0.122** |
| ch4 기울기Y | 0.249 | 0.267 | 0.066 |
| 나머지 | 0.11~0.23 | 0.17~0.24 | 0.02~0.05 |

**최대 R² = 0.12.** 중요도의 12%만 정규화 흔들림으로 설명된다. 그리고
**환자·정상 rho가 거의 같다** — 마스킹 절차는 라벨을 모르므로 절차적 효과가
군에 무관하다는 예측과 맞는다. §7.6.4에 한계로만 적었던 것이 측정값이 됐다.

> **함정 기록** — 1000ms 창(위치 3개)에서 Spearman을 쓰면 값이
> {±1, ±0.5}로 양자화되어 중앙값이 기계적으로 0.500이 된다. 처음에 그렇게
> 나와서 이상하다고 보고 200ms(위치 19개)로 다시 쟀다. **순위 상관은 위치가
> 많은 창에서만 쓴다.**

## C. 획 리듬 측정 — 내 가설이 기각됐다

`stroke_rhythm.py` 신규. 창별·채널별 지배 주파수(1~30Hz 스펙트럼 최대점)를
직접 쟀다.

| 채널 | 환자 중앙 | 정상 중앙 | 정상 4~6Hz 비율 |
|---|---:|---:|---:|
| ch2 축압력 | 7.05 Hz | 4.15 Hz | 7.4% |
| ch5 기울기Z | 7.11 Hz | **7.45 Hz** | **2.9%** |

**"정상 필기의 획 리듬이 4~6Hz대라서 정상군 기울기Z가 유의하게 나왔다"는
해석은 데이터가 지지하지 않는다.** 정상군 기울기Z의 지배 주파수는 7.45Hz이고
4~6Hz를 지배 주파수로 갖는 윈도우는 2.9%뿐이다. **초고에서 이 문장을 뺐다.**

**대신 더 나은 설명을 얻었다** — 과제별 정상군 지배 주파수(기울기 X/Y/Z):

| 과제 | 기울기 X · Y · Z |
|---|---|
| circle | 1.5 / 1.5 / 1.5 Hz |
| **meander** | **8.0 / 8.5 / 8.5 Hz** |
| **spiral** | 7.5 / 3.5 / 8.5 Hz |
| diadochokinesis | 1.0 / 1.0 / 1.0 Hz |

**필기 리듬이 과제마다 완전히 다르다.** 그리고 A에서 효과가 살아난 과제가
정확히 meander·spiral이다. "같은 대역이 과제마다 다른 의미를 갖는다"는 그림이
A와 C 양쪽에서 나온다.

부수적으로 **환자의 지배 주파수가 정상보다 높다** (축압력 7.05 vs 4.15Hz,
p<0.0001). 떨림과 부합하는 방향이다.

> **교훈** — 검증하지 않은 해석을 논문에 넣을 뻔했다. C를 안 돌렸으면
> 심사에서 물렸을 문장이다. **해석을 쓰면 그 해석을 재는 실험을 붙인다.**

## 형식 중립화

절 제목이 전부 에세이체였다. 제목(표제)만 그대로 두고 절 제목은 학술 형식으로.

`관문 — 성능이 교란에서 온 것은 아닌가` → **교란 통제**
`전제는 성립한다 — 그런데도 작동하지 않는다` → **Early Exit 성립 조건의 검증**
`왜 연결이 없는가 — 판별 정보가…` → **판별 정보의 차원**
`그럼에도 메커니즘은 실재한다 — …` → **설명 분석 — 모델의 근거 구간**
`그래서 어느 축인가` → **세 축의 비교**
`선행 연구는 왜 90%대인가 — …` → **선행 연구와의 비교**

표 캡션도 주장문에서 서술문으로 바꿨다(`표 1. 연령을 맞추면 …무너지지만 모델은
