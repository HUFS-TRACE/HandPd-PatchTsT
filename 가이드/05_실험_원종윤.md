# 05. 원종윤 — 조건 검증(③)과 원인 규명(④)

**먼저 읽기** `01_왜이연구를하는가.md`, `02_논문흐름.md`
**실험 전 확인** `08_공통규칙.md`

---

## 당신이 맡은 자리

**논문의 핵심 결과를 만든다.** "Early Exit이 왜 작동하지 않는가"에 답하는 부분
전체다. ③단계의 세 방향(깊이·시간·사람)이 모두 당신 몫이고, ④단계의 원인 규명도
여기 있다.

특히 ④단계는 논문의 심장이다. 여기까지는 "안 되더라"는 관찰이고, ④에서 처음으로 **설명**이 나온다. 결과의 나열이 논문이 되는 지점이 당신 파트에 있다.

---

## 순서

```
M0:  P0 (전처리 복원) + 준비 2가지
M1:  E1 → E2 → V2 → V3  ← 논문 방향이 여기서 갈린다
M2:  E3 → V1
```

**E1이 최우선이다.** 반나절짜리 실험인데 논문이 갈래 1로 갈지 3으로 갈지가 여기서
결정된다. 깊이 스윕(V1)은 이미 결과가 있으니 나중에 정리만 하면 된다.

**V3(시간 축)는 P0를 기다리지 않는다.** run 경계가 npz만으로 복원됨을 확인했다
(자세한 내용은 V3의 「선행 조건」). 다만 V3-[A]에서 확률을 한 번 뽑아야 하니,
그 실행은 일찍 걸어두고 [B] 분석을 하는 게 효율적이다.

**당신이 ③단계 세 방향을 전부 갖게 됐다** — 깊이(V1) · 사람(V2) · 시간(V3).

# M0 — 준비

## P0. 전처리 복원 — 논문 재현성의 전제

### 문제

**`windows_2s.npz`를 만든 코드가 존재하지 않는다.** `git log --all --diff-filter=A`로
전 이력을 뒤졌는데 원본 txt를 읽는 스크립트가 어느 커밋에도 없다. 지금 있는 npz가
어떤 규칙으로 잘렸는지 아무도 모른다.

원본에서 재현을 시도하면 이렇게 어긋난다 (2000샘플 창 / 1000 스트라이드, 50% 겹침).

| | 재현 | npz 실제 | 차이 |
|---|---:|---:|---:|
| 전체 | 13,560 | 13,474 | **+86** |
| spiral | 4,306 | 4,277 | +29 |
| meander | 3,760 | 3,729 | +31 |
| circle | 2,813 | 2,802 | +11 |
| diadochokinesis | 2,681 | 2,666 | +15 |

0.6% 어긋난다. 불일치는 (피험자 × 과제) 244쌍 중 70쌍에 +1~+3으로 흩어져 있고,
2000샘플 미만인 파일은 0개라 "짧은 파일 제외" 규칙도 아니다. **원 규칙을 모른다.**

### 왜 이게 당신 일인가

두 가지가 여기서 막혀 있다.

- **논문 재현성 절** — "전처리 코드 공개"를 쓸 수 없다. 학회가 자주 요구하는 항목이다
- **R2(임시연)와 시간 축** — 둘 다 "각 기록의 몇 번째 창인지"가 필요한데 npz에 없다

### 어떻게 — npz를 다시 만들지 말 것

**재생성하면 기존 결과 317개와 데이터가 달라져 전부 다시 돌려야 한다.** 그러지 말고
**인덱스만 사후에 덧붙인다.**

1. `data/HealthySignal/*.txt`, `data/PatientSignal/*.txt`를 읽는다
2. 각 파일에서 2000샘플 창을 1000 스트라이드로 잘라 후보 창을 만든다
3. 후보 창의 값과 `windows_2s.npz`의 `X`를 **내용으로 대조해** 대응을 찾는다
   (첫 행 몇 개만 비교하면 충분하다. 부동소수 비교라 `np.allclose`를 쓴다)
4. 매칭된 창에 `run_id`(파일명)와 `window_index`(그 기록 안에서 몇 번째)를 붙인다
5. `data/windows_2s_index.npz`로 따로 저장한다 — 기존 npz는 건드리지 않는다

**86개가 왜 빠졌는지도 이 과정에서 밝혀진다.** 매칭이 안 되는 후보 창이 곧 그
86개이고, 그것들의 공통점(파일 내 위치, 길이, 값의 성질)을 보면 원 규칙을 역산할 수
있다. 알아내면 전처리 스크립트를 재작성해 논문에 실을 수 있다.

### 산출물

| 파일 | 내용 |
|---|---|
| `preprocess.py` | 원본 txt → 윈도우. 복원된 규칙을 담는다 |
| `data/windows_2s_index.npz` | `run_id`, `window_index` (기존 npz와 행 순서 동일) |
| 짧은 메모 | 86개가 빠진 이유. 못 밝히면 "미상"으로 기록하고 넘어간다 |

### 주의

- **기존 `windows_2s.npz`를 덮어쓰지 않는다.** 지금까지의 결과 317개가 전부 무효가 된다
- 행 순서가 기존 npz와 정확히 같아야 한다. 어긋나면 인덱스가 엉뚱한 창에 붙는다
- 86개의 원인을 못 밝혀도 **P0는 성공이다.** 인덱스만 붙으면 R2와 시간 축이 열린다

### 참고 — 원본 파일 구조

사람마다 **12개 기록**이 있고 그것이 4개 과제로 묶인다.

```
circA, circB          → circle            (2회)
sigDiaA, sigDiaB      → diadochokinesis   (2회)
sigMea1 ~ sigMea4     → meander           (4회)
sigSp1 ~ sigSp4       → spiral            (4회)
```

**파일 하나가 곧 run 하나다.** run 경계를 새로 추정할 필요가 없다.

헤더에 `Person_ID_Number`, `Age`, `Gender`, `Date`, `Samplerate`(전 파일 1000)가 있다.
읽는 방식은 `build_subject_meta.py`의 `read_meta()`를 그대로 쓰면 된다.

## ① 6채널의 물리적 의미 문서화

우리 데이터는 태블릿 좌표가 아니라 **BiSP 스마트펜의 내장 센서값**이다.

| 채널 | 내용 |
|---|---|
| 1~3 | 마이크 / 그립력 / 펜촉 축압력 |
| 4~6 | 기울기·가속도 X · Y · Z |

README와 메타를 확인해 채널 순서를 정확히 확정하고 문서화한다. **이후 모든 채널별 분석의 기준**이 되므로 여기가 틀리면 전부 틀린다.

특히 **마이크 채널은 성격이 다르다.** 떨림 대역(4~6Hz)의 물리적 의미가 다른 채널과 같지 않으므로, 모든 대역 분석에서 별도로 보고한다.

## ② 과제 4종 분리 인덱스 생성

npz에 `task` 컬럼이 있다.

| 과제 | 윈도우 수 |
|---|---:|
| spiral | 4,277 |
| meander | 3,729 |
| circle | 2,802 |
| diadochokinesis | 2,666 |

**diadochokinesis는 그림 그리기가 아니라 팔을 뻗고 손목을 돌리는 검사다.** 성격이 완전히 달라서 결과 해석도 달라진다.

이후 모든 집계를 과제별로 분리할 수 있도록 인덱스를 만들어둔다.

### 주의 — 계층이 하나 더 있다

npz의 `task` 4종은 원본 12개 기록을 묶은 것이다. 실제 구조는 이렇다.

```
피험자 (61) > 과제 (4) > 기록 (2~4회 반복) > 윈도우
```

**spiral과 meander는 같은 사람이 같은 과제를 4번 반복한 것이다.** 같은 사람의
sigSp1~4는 서로 상관이 매우 높아서, 윈도우를 독립 표본처럼 다루면 유효 표본 수를
크게 과대평가한다. `08_공통규칙.md`가 지적한 "피험자당 윈도우 10배 편차"에 이
층위가 겹친다.

집계할 때 **과제별 분리에 더해 반복 기록 구조를 논문에 명시한다.** 기록 단위
인덱스는 P0의 산출물로 나온다.

# M1 — 핵심 실험

## E1. 피처 하나로 어디까지 되나 — 최우선

### 무엇을

떨림 대역 파워 하나만 뽑아서 **로지스틱 회귀**(가장 단순한 분류기)를 학습한다.

### 왜

④단계의 핵심 실험이다.

이 하나로 딥러닝에 근접하면 → **이 문제가 저차원이라는 직접 증거**가 된다. 그리고 그것이 Early Exit이 실패한 이유를 설명한다. 모든 입력이 같은 소수의 특성으로 판별되니 "어려운 입력"이라는 게 생길 수 없는 것이다.

### 어떻게

1. 피험자별로 각 채널의 4~6Hz 대역 파워를 계산한다
2. 채널별로 따로 돌린다 — 기울기 X·Y·Z와 축압력이 주 대상, **마이크는 별도 보고**
3. **`protocol.get_folds()`로 분할을 받는다.** 딥러닝과 공정 비교하려면 분할이
   완전히 같아야 하는데, sklearn 쪽에서 `GroupKFold`를 따로 만들면 `val` 분리
   방식이 달라져 어긋난다. 반드시 이 함수를 거친다

   ```python
   from types import SimpleNamespace
   from protocol import get_folds, SEEDS
   args = SimpleNamespace(n_folds=5, val_size=0.1, stratified=False, seed=42)
   for tr, va, te in get_folds(subject_id, y, args):
       clf.fit(F[tr], y[tr]); prob = clf.predict_proba(F[te])[:, 1]
   ```
   시드는 `SEEDS`(= 42, 1, 7) 세 개를 모두 돌리고 **fold × seed 원본을 남긴다**
4. 과제 4종별로도 분리 집계

### 결과 해석

| 결과 | 뜻 |
|---|---|
| 딥러닝에 근접 (예: AUC .82 이상) | 저차원 가설 강력 지지 → **갈래 1** |
| 크게 낮음 (예: AUC .70대) | 저차원 가설 기각 → **갈래 3으로 전환** |

> **이 실험 하나가 논문의 방향을 결정한다. 결과가 나오면 즉시 팀에 공유한다.**

## E2. 피처를 늘리면 언제 멈추나

### 무엇을

피처를 1개, 2개, 3개... 늘려가며 성능 곡선을 그린다.

### 왜

E1이 "하나로 얼마나 되나"라면 이건 **"몇 개면 충분한가"**다.

곡선이 소수 지점에서 평평해지고, **그 포화 지점이 딥러닝 성능과 만나면** 저차원 주장이 완성된다. "딥러닝이 하는 일을 피처 몇 개가 대체한다"는 뜻이 되니까.

### 어떻게

**후보 피처 예시**
- 대역별 파워 (저주파 / 떨림대역 4~6Hz / 고주파)
- 속도·가속도 통계량 (평균, 분산, 첨도)
- 축압력 통계량
- 그립력 통계량
- 정지 시간 비율

**추가 순서** — 단일 성능이 높은 순, 또는 순차 전진 선택(하나씩 넣어보며 가장 성능이 오르는 걸 채택)

**그림** — 가로축 피처 수, 세로축 성능. **딥러닝 성능을 수평선으로 함께 표시**한다. 곡선이 그 선에 닿는 지점이 결론이다.

### 결과 해석

곡선이 3~5개에서 평평해지고 딥러닝 선에 닿으면 갈래 1 확정.

## V2. 사람마다 난이도가 다른가

### 무엇을

세 가지를 센다.

1. **피험자별 예측 확률의 분포와 표준편차**
2. **L1과 L6에서 예측 라벨이 뒤집히는 피험자 비율**
3. **오분류가 소수에게 집중되는지, 전체에 퍼져 있는지**

### 왜

③단계의 핵심 근거다.

Early Exit의 전제가 "어려운 입력이 존재한다"인데, **지금까지 깊이 축과 시간 축만 봤고 사람 축을 직접 잰 적이 없다.** 사실 이게 전제의 본체다.

- 깊이·시간 축 → "메커니즘이 작동하지 않았다"
- 사람 축 → **"애초에 배분할 난이도 차이가 없었다"**

두 번째가 훨씬 강한 진술이다.

### 어떻게

- 피험자별 윈도우 예측 확률을 모아 분포와 표준편차 계산
- L1 모델과 L6 모델의 피험자 단위 예측을 비교해 뒤집힘 비율
- 오분류 피험자 목록을 뽑아 집중도 확인

**주의** — 피험자당 윈도우 수가 82~801로 10배 차이 난다. 분산 해석할 때 이 편차를 반드시 고려한다. 윈도우가 많은 사람의 확률 분포가 더 안정적으로 보이는 건 당연한 일이다.

### 결과 해석

| 결과 | 뜻 |
|---|---|
| 오분류가 소수에 집중 | 어려운 입력이 존재한다. 동적 축에 여지가 있음 |
| 전체에 고르게 분산 | 어려운 입력이 없다. **동적 축 무효 확정** |

## V3. 몇 초나 봐야 판단할 수 있나 — 시간 축

### 배경 — 이게 왜 당신 몫인가

③단계는 Early Exit의 전제를 **깊이·시간·사람** 세 방향에서 검증한다. 깊이(V1)와
사람(V2)은 이미 당신 몫인데 **시간 축만 담당자가 없었다.** V2와 쓰는 데이터가
같아서(피험자별 윈도우 확률) 여기 붙인다.

`02_논문흐름.md`가 "세 방향 모두 불성립"이라고 써 있었지만 **시간 축은 근거
실험이 없었다.** V3가 그 칸을 채운다.

설계는 이미 상세히 나와 있다 — **`paper/exp2_protocol.md`를 먼저 읽는다.**
아래는 그 문서를 실행 순서로 정리한 것이다.

### 무엇을

지금은 한 사람의 윈도우를 **전부** 보고 평균 내어 판정한다. 사람당 윈도우가
82~801개, 최대 27분어치다. 시간 축의 질문은 이것이다.

> 명확한 사람은 일찍 끊고, 애매한 사람만 계속 보면 되지 않나?

깊이 축 Early Exit이 "쉬운 입력은 1층에서 끊자"였다면, 시간 축은 **"쉬운 사람은
기록 2~3번에서 끊자"**다. 같은 아이디어를 층이 아니라 시간에 적용한 것이다.

증거를 하나씩 쌓다가 확신이 서면 멈추는 절차를 **SPRT(순차확률비검정)**라 한다.

```
Λ_n = Σ log[ p(x_i|PD) / p(x_i|HC) ]      증거 누적
A = log((1-β)/α)    상단 도달 → 환자 판정
B = log(β/(1-α))    하단 도달 → 정상 판정
그 사이              → 하나 더 관측
```

### 선행 조건 — 확인 완료, P0를 기다리지 않아도 된다

`stream.py`가 필요하다는 말 때문에 P0(전처리 복원)에 묶인 것처럼 보이지만
**그렇지 않다. 이미 확인했다.**

윈도우가 50% 겹침으로 시간순 저장돼 있어서, `X[i]`의 후반부와 `X[i+1]`의 전반부가
일치하는지만 보면 run 경계가 복원된다.

| 검증 항목 | 결과 |
|---|---|
| 겹침 성립 | 12,682 / 12,694 쌍 (**99.9%**) |
| 복원된 run 수 | **792** — 원본 txt 파일 수와 정확히 일치 (35×12 + 31×12) |
| run 길이 중앙값 | **14 윈도우** (약 15초) |
| 피험자당 run 수 | 중앙값 **12** — 사람당 기록 12개와 일치 |

**P0와 독립적으로 지금 시작할 수 있다.** (P0가 끝나면 `run_id`로 교차 검증하면
되고, 그때 두 방식이 일치하면 그것 자체가 P0의 검증이 된다.)

```

      ↓

**[B]에서 결과가 나쁘면 [C] 이후를 실행하지 않는다.** 학습은 [A]에서 한 번뿐이고

### [B] 사전 점검 — `analyze_drift.py` ★ 가장 중요

학습 없이 numpy 재계산만으로 **이 실험의 성립 여부가 판정된다.**

피험자 s마다:

```
윈도우별 증거      e_i = logit(p_i) - c
드리프트           d_s = mean(e_i)          한 윈도우당 평균 증거
필요 관측량 추정   n*_s = A / |d_s|         Wald 근사
```

`n*`는 **"이 사람을 판정하려면 윈도우가 몇 개 필요한가"**의 이론적 추정치다.

| 유형 | 조건 | 의미 |
|---|---|---|
| **A. 몰표** | 부호 일치 · `n* ≤ 10` | 빨리 종료. 여기서 시간이 절감된다 |
| **B. 접전** | 부호 일치 · `n* > 10` | 오래 봐야 함 |
| **C. 반대** | **부호 불일치** | 확신을 갖고 오분류 |

`n*` 임계 10은 피험자당 비중첩 윈도우 중앙값(약 82)의 12%다. 민감도 확인을 위해
**5 / 10 / 20에서 각각 세어 함께 보고**한다.

**사전 등록된 판정 기준 — 결과 보기 전에 고정한다**

| C 유형 인원 (61명 중) | 판정 | 조치 |
|---|---|---|
| 0~3명 | 진행 | [C]~[D]를 계획대로 |
| 4~7명 | 조건부 진행 | 유보 옵션과 비대칭 경계를 **필수**로. 명목 α 보장은 주장하지 않는다 |
| 8명 이상 | 재설계 | 정지 규칙이 아니라 모델 쪽 문제 |

**함께 낼 것**

- **드리프트 히스토그램** — **단봉이면 모든 피험자의 명확도가 비슷하다는 뜻이고,
  그 경우 적응적 종료의 이론적 이득이 0이다.** 고정 N개가 최적이 된다.
  ③의 결론이 사실상 여기서 나온다
- `|d_s|` vs 실제 판정 정확도 산점도 — 드리프트가 신뢰도의 대리 지표로 작동하는지
- 시드 3개에서 C 유형 인원이 재현되는지 — 시드마다 다르면 그 자체가 결과다

### [C] 캘리브레이션 — `calibrate.py`

온도 `T`와 사전확률 보정 `c`를 구한다. **반드시 val에서 정한다.** test에서 맞추면
테스트셋 피팅이다. fold마다 모델이 다르므로 **T와 c도 fold별로 따로** 구한다.

> `--save-probs`는 현재 test 확률만 저장한다. [C]를 하려면 val 확률도 필요하니
> `evaluate.py`에 val 추론을 한 번 더 붙여야 한다. **함정** — test는 GroupKFold라
> fold를 가로질러 전체를 한 번씩 덮지만 **val은 fold마다 겹칠 수 있다.**
> test용 중복 검사를 val에 그대로 쓰면 터진다. val은 fold 태그를 붙여 fold별로만 쓴다.

### [D] 본 실험 — `stream.py` · `sequential_exit.py`

**`stream.py`**

| 함수 | 역할 |
|---|---|
| `build_runs(subject_id, task)` | subject/task가 바뀌는 지점을 경계로 run 번호 부여 |
| `verify_overlap(X, run_id)` | `X[i]` 후반부 == `X[i+1]` 전반부 검증. **순차 실험 전 필수** |
| `subject_streams(..., subsample)` | `{subject: [run별 인덱스]}`. `subsample=True`면 run 안에서 `[::2]` |

**왜 run 단위인가**

1. run 내부 인접 윈도우는 50% 겹쳐 독립이 아니다 → `[::2]`로 솎으면 정확히 비중첩
2. run 사이에는 겹침이 없다 → run 단위로 멈추면 독립성이 자동 확보
3. 임상적으로 정지 단위가 "과제를 한 번 더 시킬 것인가"가 되어 자연스럽다

**`sequential_exit.py`**

| 함수 | 역할 |
|---|---|
| `llr(prob, prior_logit)` | `logit(p) - c`. 수치 안정 위해 확률 클리핑 |
| `boundaries(alpha, beta)` | Wald 경계 A, B |
| `run_sprt(...)` | run 경계에서만 확인. **미도달 시 유보(-1)** |
| `run_fixed_runs(..., R)` | run R개만 보고 판정 — *같은 정지 단위의 baseline* |
| `run_fixed(..., k)` | 윈도우 k개 (참고용) |
| `run_random(..., k)` | 무작위 k개 — **시간 순서 정보가 쓸모 있는지 가르는 대조군** |

**유보(defer)를 처음부터 넣는다.** 경계 미도달 시 부호로 판정을 강제하지 않는다.

> **주의** — 유보를 도입하면 판정률이 낮아질수록 판정 정확도가 자동으로 올라간다.
> **판정률과 정확도는 반드시 쌍으로 보고한다.** 정확도만 떼면 무의미한 숫자다.

**비대칭 경계를 처음부터 지원한다.** 스크리닝은 위음성(환자 놓침)이 위험하므로
β를 α보다 작게 잡는 영역이 관심 대상이다.

**실행 설계**

| 축 | 값 |
|---|---|
| 확률 공급원 | 정적 `p16d128L1` |
| 정지 단위 | **run**(기본) / window |
| 스트림 | **비중첩**(기본) / 겹침(비교용만) |
| 시드 | 42 / 1 / 7 — 전 과정 반복, 평균 ± 표준편차 |
| 경계 | α 4개 × β 4개 = 16 |
| baseline | all / fixed-R / fixed-N / random-N |

```bash
python stream.py --data-path data/windows_2s.npz     # 먼저 겹침 검증

for s in "" "_s1" "_s7"; do
  python sequential_exit.py     --probs results/probs_p16d128L1_depth_2s${s}.npz     --calib results/calib_p16d128L1${s}.json     --unit run --alphas 0.30 0.20 0.10 0.05 --betas 0.10 0.05 0.02 0.01
done
```

|---|---|---|---|---|
| 0.05 | 0.05 | ? | ? | ? |

명목과 실측이 크게 어긋나면(예상되는 결과다) **실패가 아니라 보고 가능한 결과다.**

## E3. 채널 하나씩 빼보기

### 무엇을

6채널 중 하나씩 제거하며 성능 변화를 본다.

### 왜

④의 "정보 차원이 낮다"를 **채널 수준에서** 확인한다. 6개가 다 필요한지, 2~3개면 되는지.

E1·E2가 "몇 개의 피처가 필요한가"라면, 이건 "몇 개의 센서가 필요한가"다. 실용적으로도 의미가 있다 — 센서를 줄이면 기기가 더 싸진다.

### 결과 해석

소수 채널만 기여하면 저차원 주장이 강화된다.

> **갈래 3(E1이 실패한 경우)에서는 이 실험이 본체가 된다.** 질문이 "몇 개의 특성인가"에서 "어느 채널인가"로 바뀌기 때문이다.

## V1. 깊이 스윕 정리

### 무엇을

L1 / L2 / L3 / L6 × 시드 3개 결과를 표로 정리한다.

### 재실행 불필요

**기존 30회 스윕 결과가 이미 있다.** 정리만 하면 된다. 여유가 없으면 박민규에게 넘겨도 되는 작업이다.

### 주의 — L3는 참조 모델로 쓰지 않는다

이전 표는 한 열에 AUC(.8664)와 윈도우 정확도(.7536)를 섞어 놓아서 "L3가 유독
낮다"가 실제보다 커 보였다. **지표별로 나눠 본다** (3시드 평균).

| 모델 | 윈도우 AUC ← 주 지표 | 윈도우 정확도 | 피험자 정확도 | MFLOPs |
|---|---:|---:|---:|---:|
| L1 | **.8664** | .7805 | .8846 | 588 |
| L2 | .8624 | .7847 | .8679 | 1,170 |
| L3 | .8497 | **.7536** | .8086 | 1,752 |
| L6 | .8629 | .7847 | .8790 | 3,499 |

**주 지표(AUC)에서 L3의 편차는 .014로, 시드 간 재현 오차 ±.011의 1.3배에 그친다.**
윈도우 정확도에서만 눈에 띄게 낮다. "원인 미상의 이상치"라고 쓰면 과장이다.

논문에는 이렇게 쓴다.

> L3는 윈도우 정확도에서 가장 낮고 AUC에서도 최저였으나, 그 편차는 시드 간
> 재현 오차 수준이었다. 깊이에 따른 단조적 경향은 어느 지표에서도 관찰되지 않았다.

`train.py` 기본값이 `n_layers=3`이라 인자 없이 실행하면 하필 이 설정이 돌아가던
문제는 **기본값을 6(참조 모델과 동일)으로 바꿔 해결했다.**

기준 모델은 `08_공통규칙.md` §3을 따른다 — 참조 **L6**, 깊이 축 경량 **L1**,
정적 축 대표 **d64L2**.
