# S0 — 선행 연구 조사

> **오늘 착수한다. 반나절이면 된다. 지금 팀 전체에서 가장 값싸고 효과 큰 작업이다.**

## 왜 당신인가

원래 팀장 몫이었는데 당신에게 넘겼다. 이유가 있다.

**당신이 R4·R5로 찾아낼 것이 곧 이 조사의 대상**이기 때문이다. 교란을 실험으로
다루는 사람이 선행 연구의 교란 처리도 같이 보는 게 맞다. 그리고 이 조사 결과에
따라 **당신의 R4·R5가 "보조 실험"이 될지 "논문의 본체"가 될지가 갈린다.**

학습이 없으니 R0를 돌려놓고 그동안 하면 된다.

## 무엇을 조사하나

**NewHandPD(또는 HandPD) 데이터셋을 사용한 논문**을 모아, 다음 셋을 다룬 사례가
있는지 확인한다.

| # | 확인할 것 | 우리 발견 |
|---|---|---|
| 1 | **피험자 중복 / 파일번호 기반 분할의 누수** | 66개 파일번호 = 61명. P1=P4, P9=P10, P15=P17, P2=P25=P26, H34에 두 사람 |
| 2 | **수집 시기 교란** | 2016년 수집 21명 전원 정상 (61명 중 34%) |
| 3 | **연령 불균형 통제** | 정상 43.3세 / 환자 58.0세. 나이 규칙 단독 73.8% |

1번이 특히 중요하다. **파일번호로 train/test를 나눈 논문은 같은 사람이 양쪽에
들어가 성능이 부풀려졌을 수 있다.** 논문에 분할 방식이 적혀 있으면 그것만으로
판정된다.

## 어떻게

**검색어** — Google Scholar · IEEE Xplore · PubMed에서

```
"NewHandPD"
"HandPD" Parkinson handwriting
"HandPD" dataset signal
Parkinson smart pen handwriting classification
NewHandPD Papa OR Pereira      (데이터셋 원저자)
```

원 데이터셋 논문의 **피인용 목록을 훑는 것이 가장 빠르다.** 인용 수가 많지 않을
테니 전수 조사가 가능하다.

**목표는 15~20편.** 완벽할 필요 없다. 전수에 가까우면 좋지만, 못 채워도
"확인한 N편 중"이라고 정직하게 쓰면 된다.

## 무엇을 기록하나

논문마다 이 표 한 줄. **표 자체가 논문에 들어간다.**

| 논문 | 연도 | 피험자 수 표기 | 분할 방식 | 중복 언급 | 시기 언급 | 연령 통제 | 보고 성능 |
|---|---|---|---|---|---|---|---|
| (예) A et al. | 2019 | **66명** | 파일 단위 랜덤 | ✗ | ✗ | ✗ | 92.1% |
| (예) B et al. | 2021 | 61명 | 피험자 단위 | ○ | ✗ | ✗ | 84.3% |

- **피험자 수 표기** — 66이라고 쓴 논문은 중복을 인지하지 못한 것이다
- **분할 방식** — "random split", "5-fold CV"만 적혀 있고 그룹 키 언급이 없으면
  누수 가능성을 의심한다. 단정하지는 말고 **"명시되지 않음"**으로 기록한다
- **보고 성능** — 나중에 "누수 의심 논문일수록 성능이 높은가"를 볼 수 있다.
  경향이 보이면 그 자체가 강력한 근거가 된다

## 결과에 따라 무엇이 달라지나

| 조사 결과 | 논문에서의 의미 |
|---|---|
| **교란을 다룬 논문이 0편** | **1순위 기여로 올린다.** 초록 첫 문장에 들어간다. 갈래 2에서는 결정적 |
| 1~2편이 부분적으로 언급 | 기여로 유지하되 "선행 연구가 지적한 바를 정량화하고 통제 프로토콜을 제안했다"로 톤 조정 |
| 이미 충분히 다뤄짐 | 기여를 ③④(Early Exit 조건 형식화)로 옮긴다. **논문 구조를 다시 짠다** |

> "이 데이터셋을 쓴 논문 N편 중 교란을 다룬 게 0편"이라는 문장 하나가 발표를
> 완전히 바꾼다. **"우리 실험 안 됐어요"에서 "이 분야가 놓치고 있던 걸
> 찾았습니다"로.**

## 반드시 지킬 것 — 톤

**선행 연구를 비난하지 않는다.** 이건 논문의 신뢰도 문제이자 예의의 문제다.

- ✅ "이 한계 하에서 해석되어야 한다"
- ✅ "본 연구는 해당 구조를 정량화하고 통제 프로토콜을 제안한다"
- ❌ "기존 연구는 틀렸다"
- ❌ "누수로 인해 성능이 과대평가되었다" (단정)

우리도 데이터를 열어보고서야 알았다. 우리 전처리가 `Person_ID_Number`로 나눈 건
운이 좋았던 면도 있다.

## 결과 공유

**조사가 끝나면 즉시 팀에 공유한다.** M1 회의를 기다리지 않는다. 이우림이 논문
골격을 짤 때 이 결과가 필요하고, 골격이 늦어지면 초고가 밀린다.

# M0 — 완료됨. 바로 M1로 들어간다

원본 signal 데이터가 들어오면서 M0 항목이 전부 산출됐다. **다시 만들 필요 없다.**
재현이 필요하면 `python build_subject_meta.py` 한 번이면 된다.

| 산출물 | 위치 | 내용 |
|---|---|---|
| 피험자 메타 | `data/subject_meta.csv` | 61명 × 라벨·나이·성별·수집연도·파일번호 |
| R4 명단 | `data/subset_R4.txt` | 40명 (정상 14 / 환자 26) |
| R5 명단 | `data/subset_R5.txt` | 41명 (정상 17 / 환자 24) |

**확정된 수치 — 논문에 그대로 쓴다**

| 항목 | 값 |
|---|---|
| 피험자 정제 | 66 파일번호 → **61명**. P1=P4, P9=P10, P15=P17, P2=P25=P26, H34 폴더에 2명(그중 1명은 H29와 동일인) |
| 나이 | 정상 43.3세(14–79) / 환자 58.0세(38–78), 차이 **+14.7세** |
| 수집 연도 | 2010 정상5/환자2 · 2011 정상9/환자23 · 2012 정상0/환자1 · **2016 정상21/환자0** |
| 성별 | 정상 남17/여18 · 환자 남17/여9 (환자 남성 65.4%) |
| R4 검증 | 날짜(`#<Date>`) 기준과 ID 코드(603/604/605) 기준이 **완전히 같은 집합** |

**클래스 가중 재계산** — 새로 짤 것 없다. `--auto-class-weight` 플래그가 fold의
train 분포에서 역빈도로 다시 계산한다. 서브셋에서는 이쪽이 주 실험이다.

R4 서브셋의 실제 윈도우 편중을 미리 적어둔다. 전체는 정상:환자 = 1:1.77인데
**R4는 2,026 : 8,607 = 1:4.25로 훨씬 심해진다.** 고정 가중 `[2.0, 1.0]`의 근거가
완전히 사라지는 지점이다.

## 서브셋 겹침 — 논문 한계 절의 핵심 수치

| 서브셋 | 인원 | 정상 | 환자 | 나이차 |
|---|---:|---:|---:|---:|
| 전체 | 61 | 35 | 26 | +14.7세 |
| R4 (2016 제외) | 40 | 14 | 26 | **+11.3세** |
| R5 (나이 ≥45) | 41 | 17 | 24 | +3.3세 |
| **R4 ∩ R5** | **32** | **8** | **24** | +1.4세 |

두 가지를 읽어야 한다.

**하나 — R4는 나이를 통제하지 못한다.** 2016년을 빼도 나이차가 +11.3세로 거의
그대로 남는다(전체 +14.7세). 그래서 R4를 통과해도 연령 교란은 배제되지 않으며,
**R5가 별도로 필요한 이유가 여기 있다.** 두 관문을 모두 통과해야 ②가 닫힌다.

**둘 — 동시 통제는 불가능하다.** 둘 다 적용하면 정상이 8명뿐이라 3-fold로도
fold당 2.7명이다. AUC를 잴 수 없다. "61명 규모에서 시기와 나이를 동시에 통제하는
것은 불가능하다"를 **한계가 아니라 발견으로** 쓴다.

# M1 — 관문 실험

## R0. 비교 기준점 만들기

### 무엇을

전체 61명을 **3-fold × 시드 3개**로 학습한다.

### 왜

R4·R5는 사람이 40명대로 줄어서 3-fold로 돌린다. 5-fold면 test fold당 정상이 2.8명밖에 안 되어 AUC가 사실상 노이즈다.

그런데 이 결과를 기존 5-fold 결과와 비교하면 문제가 생긴다. **성능이 떨어졌을 때 사람이 줄어서인지 fold가 줄어서인지 구분할 수 없다.**

전체 데이터를 같은 3-fold 조건으로 한 번 돌려두면 순수한 비교가 된다.

### 어떻게

데이터·모델 그대로, 분할만 3-fold, 시드 `[42, 1, 7]`.

```powershell
foreach ($s in 42,1,7) {
  python evaluate.py --config configs/protocol.yaml `
    --suite depth --configs p16d128L1 --n-folds 3 --seed $s
}
```

산출: `results/folds_depth_p16d128L1_2s_fold3_s*.csv` — **fold별 원본 수치**가
행 단위로 쌓인다. P2(TOST)와 신뢰구간이 이 파일을 읽는다. 평균만 담긴
`pareto_*.csv`로는 검정을 못 하니 folds 파일을 반드시 보존한다.

### 결과 해석

이 값이 R4·R5의 비교 원점이다. **R4·R5의 "성능 유지" 판정은 5-fold 결과가 아니라 이 값과의 비교다.**

> ⚠️ **반드시 R4·R5보다 먼저.** 기준점 없이 서브셋 결과만 보면 판정할 수 없다.

## R4. 2016년 배치 빼고 다시 학습 — 관문

### 무엇을

2016년 수집 21명(전원 정상)을 제외하고, 2010~2012년분 40명(정상 14 / 환자 26)으로만 학습·평가한다.

### 왜

2016년 사람이 전원 정상이므로, 모델이 "2016년 신호의 특징"만 배워도 21명을 완벽히 맞힌다. 이들을 빼면 시기로 맞히는 길이 막힌다.

### 어떻게

- 3-fold × 시드 3개 `[42, 1, 7]` — 전체 실험과 동일. `08` §2 참조
- 클래스 가중 재계산본 + 고정값 `[2.0, 1.0]` **두 조건 다**
- 주 실험은 L1(4.4분), L6에서 확인 재현(65~100분)

```powershell
# 주 실험 — 가중 재계산
foreach ($s in 42,1,7) {
  python evaluate.py --config configs/protocol.yaml `
    --suite depth --configs p16d128L1 `
    --subjects-file data/subset_R4.txt --n-folds 3 --auto-class-weight --seed $s
}
# 대조 — 고정 가중 [2.0, 1.0]
foreach ($s in 42,1,7) {
  python evaluate.py --config configs/protocol.yaml `
    --suite depth --configs p16d128L1 `
    --subjects-file data/subset_R4.txt --n-folds 3 --seed $s
}
```

두 조건의 결과 파일이 `_autocw` 태그로 자동 분리된다. R5는 `subset_R5.txt`로
바꾸기만 하면 된다.

**`d64L2`도 함께 돌린다.** 논문이 최종 권하는 모델이 교란 통제 하에서도 버티는지
직접 보여야 한다. 38 MFLOPs라 L1(588)보다 15배 싸서 비용 부담이 없다.

```powershell
foreach ($s in 42,1,7) {
  python evaluate.py --config configs/protocol.yaml `
    --suite size --configs d64L2 `
    --subjects-file data/subset_R4.txt --n-folds 3 --auto-class-weight --seed $s
}
```

L1과 `d64L2`가 같은 방향이면 결론이 훨씬 단단해진다. 갈리면 그것도 보고할
결과다 — 어느 표현이 교란에 더 의존하는가.

### 결과 해석

| 결과 | 뜻 |
|---|---|
| R0 대비 성능 유지 | 2016 배치가 근거가 아니었다. **통과** |
| 성능 붕괴 | 모델이 시기 차이를 학습했다. **갈래 2로 전환** |

### 반드시 지킬 것

- **점추정으로 보고하지 않는다.** 40명이라 추정이 불안정하다. 신뢰구간을 함께 낸다
- **"유의하지 않았다"를 "차이 없다"로 쓰지 않는다.** 40명에서는 검정력이 부족해서 못 잡았을 수 있다. P2에서 TOST를 쓰는 이유와 같은 논리다
- **결과가 나오면 회의를 기다리지 말고 즉시 팀에 공유한다**

## R5. 나이 맞춘 사람들로만 다시 학습 — 관문

### 무엇을

45세 이상만 남긴다. 정상 17 / 환자 24, 총 41명. 평균 나이 차이가 **14.7세 → 3.3세**로 줄어든다.

### 왜

나이 규칙 하나로 **73.8%**(≥52세)가 맞는 상황이다. 모델이 파킨슨이 아니라 "나이 든 사람의 필기"를 학습했을 수 있다.

### 왜 하필 45세인가

| 서브셋 | 정상 | 환자 | 나이차 | 판단 |
|---|---:|---:|---:|---|
| 전체 61명 | 35 | 26 | +14.7세 | 교란 심함 |
| 나이 ≥ 38 | 24 | 26 | +6.2세 | 여전히 큼 |
| **나이 ≥ 45** | **17** | **24** | **+3.3세** | **채택** |
| 2010~2012 & ≥38 | 10 | 26 | +3.0세 | 정상 10명, 불가 |

마지막 것이 나이차는 가장 작지만 정상이 10명뿐이라 3-fold로도 fold당 3.3명이라 쓸 수 없다.

> **즉 시기와 나이를 동시에 통제하는 건 이 데이터셋으로 불가능하다.** 이 사실 자체를 논문 한계에 명시한다. 중요한 결론이다.

### 어떻게

R4와 동일 (3-fold × 시드 3, 가중 재계산, L1 주 실험 + L6 확인, 채널별 분리)

### 추가 — 채널별 분리 보고

나이는 떨림뿐 아니라 그립력·필압·움직임 속도에도 영향을 준다. **채널마다 영향이 다를 수 있다.** 어느 채널이 나이에 민감한지 보면 그 자체로 정보가 된다.

### 결과 해석

| 결과 | 뜻 |
|---|---|
| 성능 유지 | 나이가 근거가 아니었다. **통과** |
| 성능 붕괴 | 상당 부분이 나이 대리 신호였다. **갈래 2로 전환** |

## R1. 떨림 대역을 지우고 다시 학습

### 무엇을

4~6Hz 대역을 필터로 제거한 뒤 재학습한다.

### 왜

파킨슨 안정떨림이 4~6Hz다. 모델이 이걸 근거로 쓴다면 지웠을 때 성능이 무너져야 한다.

> **R군에서 이 실험만 "무너져야 정상"이다.** 나머지는 전부 "유지돼야 정상".

### 어떻게

대역차단 필터 적용 후 재학습. **채널별 분리 보고** — 마이크 채널은 이 대역의 물리적 의미가 다르므로 별도로 낸다. 기울기 X·Y·Z와 축압력이 주 대상.

### 결과 해석

| 결과 | 뜻 |
|---|---|
| 성능 붕괴 | 떨림을 근거로 쓴다. 정상 |
| 성능 유지 | 떨림이 아닌 다른 걸 본다. ④⑤의 대역 기반 서술 철회 |

### ⚠️ 혼자서는 해석이 안 된다

4~6Hz 떨림은 나이가 들어도 어느 정도 증가한다. 성능이 무너져도 다음 둘이 구분되지 않는다.

- 모델이 **파킨슨 떨림**을 봤다 → 논문의 주장
- 모델이 **고령**을 봤다 → 교란

**반드시 R5 결과와 함께 해석한다.**

*부분적 방어 논거: 생리적 떨림은 보통 8~12Hz대라 4~6Hz는 파킨슨에 상대적으로 특이적이다. 논문에서 쓸 수 있다.*

### 무엇을

# M2 — 나머지 실험

## R2. 신호 앞뒤를 잘라내고 다시 학습

### 무엇을

각 run(한 번의 기록)의 첫 윈도우와 마지막 윈도우를 빼고 학습한다.

### 왜

기록 시작할 때 손 위치를 잡는 동작, 끝날 때 펜을 떼는 동작이 들어 있다. 이런 게 두 집단에서 체계적으로 다르면 모델이 그것만 볼 수 있다.

### 선행 조건

**윈도우마다 "어느 기록의 몇 번째 창인지"가 필요한데, 현재 npz에는 없다.**
`X, y, subject_id, task` 넷뿐이라 순서를 복원할 수 없다.

이건 **원종윤이 맡은 전처리 작업(P0)의 산출물**이다. `run_id`·`window_index`가
붙은 npz가 나오면 그때 착수한다. 그 전에는 R2를 시작할 수 없으니 M2의 다른
항목(R3·P1·P2·P3)을 먼저 돌린다.

기존 `windows_2s.npz`를 다시 만드는 게 아니라 **인덱스만 덧붙이는** 방식이라,
지금까지 나온 결과는 그대로 유효하다. (자세한 내용은 `05_실험_원종윤.md` P0)

### 결과 해석

유지되어야 정상. 무너지면 시작/종료부 아티팩트에 의존한 것이다.

## R3. 진폭 정보의 기여 확인

### 무엇을

RevIN(정규화 모듈)을 끄고 학습해서, 켰을 때와 비교한다.

### 왜 원래 계획에서 바뀌었나

원래는 "진폭을 정규화해서 크기 차이가 shortcut인지 본다"였다. 그런데 **RevIN이 이미 윈도우별·채널별로 정규화하고 있다.** 진폭 차이는 이미 차단돼 있어서, 현재 명세대로 하면 "아무것도 안 바꾸고 재학습"이 된다.

방향을 반대로 바꿔서, 진폭 정보를 살렸을 때 어떻게 되는지 본다.

### 결과 해석 — 단정하지 않는다

RevIN을 끄면(진폭 정보를 살리면) 성능이 오를 수 있다. 그런데 그게 shortcut인지 진짜 병리 신호인지 모른다. **파킨슨의 micrographia(글씨가 작아지는 증상)는 실제 증상이기 때문이다.**

**"진폭 정보의 기여 여부"로 중립 서술한다.**

## P1. 계산량과 속도 실측

### 무엇을

L1~L6과 경량 ML 전부의 FLOPs, 파라미터 수, CPU 추론 시간, 메모리를 잰다.

### 왜

⑥의 가로축이다. "가볍다"를 숫자로 만들어야 주장이 성립한다.

### 어떻게

- **CPU 기준.** 저비용 스크리닝이 주장이므로 GPU 숫자는 의미가 없다
- 배치 크기·스레드 수·하드웨어를 명시
- 워밍업 후 100회 반복, 중앙값과 IQR
- FLOPs 산출 도구(`thop`/`fvcore`/`ptflops` 중 하나)를 통일하고 논문에 명시

## P2. "차이 없음"을 제대로 주장하기 (TOST)

### 무엇을

L1 vs L6 등의 성능이 통계적으로 **동등**한지 검정한다.

### 왜

`p > 0.05`는 "차이가 없다"의 증거가 아니라 **"차이를 못 찾았다"**일 뿐이다. 동등성을 주장하려면 TOST라는 별도 검정이 필요하다.

통계 전공자가 심사에 있으면 정확히 여기가 찔린다.

### 어떻게

- **등가 마진 0.02.** 실험 **전에** 확정하고 기록한다. 결과 보고 정하면 사후 조작으로 의심받는다
- 근거 두 줄을 논문에 남긴다
  1. 시드 간 재현 오차(±0.011)의 약 2배
  2. 61명 규모에서 임상적으로 무시 가능한 차이
- 대응 단위 fold × seed = 15
- 대상: L1 vs L6, L2 vs L6, 경량 ML vs L6

> **이 마진은 전체 데이터 전용이다. 서브셋(R4·R5)에는 재사용하지 않는다.** 서브셋은 표본이 작아 분산이 크다.
